# 备份恢复机制改造方案

> 状态：设计已确认，待实施（2026-10-19）。
> 适用范围：`help/storage/`（`Backup` / `Restore` / `BackupSelectorConfig` / `BackupInfoHelper` / `BackupFileValidator`）、`help/AppWebDav.kt`、`help/config/LocalConfig.kt`、备份恢复相关 UI。
> 本文是一次性改造方案；按项目约定保留在 `docs/archive/`，实现完成后如结论已沉淀进代码与规范则删除或下沉。
> **代码永远比文档准确**：文中符号名用于导航，具体实现以代码为准。

## 1. 已确认的决策

| 决策点 | 结论 | 理由 |
| --- | --- | --- |
| 默认恢复策略 | **合并（Merge）** | 只补不删，恢复永不丢本地数据；覆盖作为显式选项 |
| 章节目录备份范围 | **只备「有缓存目录的书」** | 覆盖离线可读的真实需求，体积可控；全量目录作为高级开关（默认关） |
| 恢复前快照 | **默认开启**，滚动保留 3 份 | 给用户回滚路径，成本低（快照不含缓存/图片） |
| 整包加密 | **默认关闭** | 保留手动解压查看能力；用户显式开启时才加密 |

## 2. 现状问题

| 编号 | 问题 | 代码位置 | 影响 |
| --- | --- | --- | --- |
| D1 | 恢复书架时 `bookDao.deleteAll()`，`BookChapter` 对 `Book` 的外键 `onDelete = CASCADE` 级联清空章节目录 | `Restore.restore()` / `Restore.restoreSelectedFiles()`；`entities/BookChapter.kt` | 目录丢失，离线缓存无法打开 |
| D2 | 普通备份不含章节目录；选择器「章节目录」映射到 `bookChapter.json` 但备份流程只产 `bookChapterCache.json`，且仅勾选「书籍缓存」时才产 | `BackupSelectorConfig.allItems`、`Backup.backup()`、`stageBookChapterForCache()` | 用户以为备份了目录，实际没有 |
| D3 | 全量恢复在包内文件缺失时仍先 `deleteAll()` | `Restore.restore()` 各段落 | 部分备份 + 全量恢复 = 清库 |
| D4 | 除阅读记录外无事务包裹，逐表独立提交 | `Restore.*` | 中途取消/异常留下半恢复状态 |
| D5 | `lastBackup` 在备份开始时写入；云端上传失败只记日志 | `Backup.backup()`、`AppWebDav.backUpWebDav()` | 上传失败后 24h 内不重试，云端长期无新备份 |
| D6 | 备份文件名只有日期 + 设备名；`onlyLatestBackup` 下所有设备写同一个 `backup.zip` | `Backup.getNowZipFileName()` | 同日多次、多设备互相覆盖 |
| D7 | 包内无 manifest、无格式版本、无校验和 | 全库 | 无法判断包内容、来源与完整性 |
| D8 | 未设备份密码时 AES 密钥固定为 `MD5("")`；整包仍是明文 | `BackupAES` | 云端存明文书源/书单/历史 |
| D9 | 缓存书先全目录复制到 staging 再整体压缩；每次全量重传 | `Backup.stageBookCache()`、`ZipUtils.zipFiles()` | 双倍 IO、流量浪费 |
| D10 | 恢复后不重建运行时状态，只调用 `ThemeConfig.applyDayNight()` | `Restore.restore()` 收尾 | 内存旧配置、列表不刷新 |

## 3. 目标模型

### 3.1 三条硬规则

1. **包内未声明的条目，不允许产生任何删除动作。**
2. **默认合并**；覆盖必须显式选择，且恢复前生成快照。
3. **书与章节同生共死**：章节要么随包恢复，要么原样保留，绝不被书架操作连带清空。

### 3.2 结构

```
包/目录 → RestorePlan.build(path, selection, policy)
        → 校验（manifest + CRC，v1 包跳过）
        → 阶段 A：数据库（单事务，按依赖顺序 upsert / replace）
        → 阶段 B：文件与配置（staging → 原子替换，失败回滚）
        → 收尾：重建运行时状态、广播事件、按需重启
```

### 3.3 核心数据结构（示意）

```kotlin
enum class RestorePolicy { Merge, Replace }

enum class EntryKind { Db, Prefs, ConfigDir, Files }

enum class EntryStrategy {
    Upsert,          // 只插入/更新，不删除
    ReplaceIfPresent,// 包内存在该条目时 deleteAll + insert
    ReplaceAll,      // 阅读记录等需要整体重建的条目（仍在事务内）
    DirectorySync,   // 目录类：按文件级合并（缓存、封面图集、背景图）
}

data class BackupEntry(
    val name: String,
    val kind: EntryKind,
    val strategy: EntryStrategy,
    val required: Boolean = false,
)

data class RestorePlan(
    val format: Int,                 // 1 = 旧包，2 = manifest
    val entries: List<BackupEntry>,
    val policy: RestorePolicy,
    val sourcePath: String,
) {
    fun contains(name: String): Boolean
}
```

`RestorePlan.build()` 规则：

- **v2 包**：读 `manifest.json` 的 `entries`，按 manifest 生成计划；`policy` 由用户在恢复对话框选择，覆盖条目的默认策略。
- **v1 包（无 manifest）**：按 `Backup.backupFileNames` 中「实际存在」的文件/目录推导计划，视为 `Merge` 语义，**修复 D3**。
- 选择器恢复：用户勾选结果进一步过滤计划，二者取交集。

## 4. P0：数据安全

目标：先保证「不可能丢数据」，不改变包格式。

### P0-A 恢复语义改造

1. 合并 `Restore.restore()` 与 `Restore.restoreSelectedFiles()` 为一份计划驱动实现（当前两份逻辑基本是复制粘贴，改一处漏一处）。
2. 每个数据库条目声明策略：
   - `Merge`（默认）：`insert(REPLACE)`。书架、书源、书籍分组、书签、订阅源/收藏、源订阅、替换规则、TTS、词典、键盘辅助、服务器配置、直链规则、首页模块。
   - `ReplaceIfPresent`：仅 `policy == Replace && plan.contains(name)` 时 `deleteAll()`，否则只 upsert。
   - `ReplaceAll`：阅读记录（clear + import + repair，保留现有事务），同样要求 `plan.contains()`。
3. **书架恢复改为纯 upsert**：`Book` 主键 `bookUrl`、`BookDao.insert` 为 `OnConflictStrategy.REPLACE`，不需要 `deleteAll()`。这样 D1 的级联删除没有触发机会。
4. 覆盖模式下仍保护章节：
   - 执行前把现有 `book_chapter` 按 `bookUrl` 快照到临时 JSON；
   - 恢复完成后，对「包内无目录且书仍存在」的书籍回填章节。
5. 全量恢复（未开选择器）同样走计划，不再出现「文件缺失也删表」。
6. `restoreBookCache()` 补充：包内没有 `bookChapterCache.json` / `bookChapter.json` 时，不清空现有章节。

### P0-B 章节目录成为一等公民

1. 新增备份条目 `bookChapter.json`：
   - 遍历 `book_cache` 下实际存在的书籍目录，用 `appDb.bookDao.all.associateBy { it.getFolderName() }` 反查 `Book`；
   - 导出这些书的 `book_chapter` 行（字段与实体一致）；
   - 全量目录作为高级开关，默认关闭。
2. 恢复时按 `bookUrl` 分组：`delByBook(bookUrl)` + `insert`。若书籍不存在，跳过（并记日志）。
3. 修正选择器：
   - `BackupSelectorConfig.allItems` 中 `bookChapter` 的 `fileName` 改为 `bookChapter.json`；
   - `BackupSelectorViewModel.overviewFileName()` 删除 `"bookChapter" -> "bookChapterCache.json"` 的特殊映射；
   - `BackupInfoHelper.isFileSelectedForBackup()` / `isFileEnabledForRestore()` 同步；
   - `Backup.backup()` 与 `Restore` 中真正处理 `bookChapter.json`。
4. 恢复顺序固定：books → chapters → 其他表 → 缓存文件，保证外键与匹配逻辑成立。

### P0-C 事务、快照与收尾

1. **数据库单事务**：所有 DB 步骤包进 `appDb.withTransaction { }`（项目已有先例：阅读记录恢复）。
2. **文件/配置两阶段**：
   - 背景图、封面图集、`book_cache`、`ReadBookConfig` / `ThemeConfig` 配置文件先写 staging；
   - 逐项原子替换：旧文件改 `.bak`，全部成功后删除 `.bak`；失败则还原。
   - SharedPreferences 恢复前把受影响 key 的原值写入 `restore_rollback.json`，失败自动回滚。
3. **恢复前自动快照**（默认开）：
   - 复用 Backup，只导数据库 JSON + 配置（**排除** `book_cache`、`bg`、封面图集）；
   - 命名 `pre_restore-{yyyyMMdd-HHmmss}.zip`，滚动保留 3 份；
   - 恢复失败时提示可回滚。
4. **恢复前静默**：保存 `ReadBook` 进度 → `CacheBook.close()` → `ExoPlayerHelper.releaseAllBookCaches()`，避免 media3 目录锁。
5. **恢复后重建**：
   - 发 `BOOKSHELF_REFRESH` 等 LiveEventBus 事件；
   - 配置变更提示重启，或直接重启进程（推荐，状态最干净）。
6. **时间戳与命名**：
   - `LocalConfig` 拆为 `lastBackupAttempt` / `lastLocalBackupSuccess` / `lastCloudBackupSuccess`；
   - 自动备份：本地 > 24h 触发；云端已配置 WebDAV 且 > 24h 未成功则重试（退避 1h → 6h → 24h）；
   - 上传成功才更新云端时间；
   - 文件名 `backup-{yyyyMMdd-HHmmss}-{设备名}.zip`；`onlyLatestBackup` → `backup-latest-{设备名}.zip`；前缀仍为 `backup`，兼容现有列表逻辑。

### P0 验收

- 4 类包 × 2 策略矩阵：
  - 全量包 / 仅书源包 / 仅书架包 / 无 manifest 旧包；
  - Merge / Replace。
- 断言：
  - 恢复「仅书源」包后 `books`、`book_chapter` 行数不变；
  - 恢复「仅书架」包后章节数不变；
  - Replace 模式且包内无目录时，章节被回填，缓存书可打开。
- 断网 + 清空书源后，已缓存书籍仍能打开（依赖目录 + `CacheManifestHelper`）。
- 备份/恢复中途杀进程：不产生半恢复状态；`lastLocalBackupSuccess` 不更新。

## 5. P1：包格式与可验证性

### 5.1 `manifest.json`（格式 v2）

```json
{
  "format": 2,
  "createdAt": 1790000000000,
  "appVersionCode": 260,
  "dbVersion": 100,
  "deviceName": "MuMu",
  "scope": "local",
  "policyHint": "merge",
  "encrypted": false,
  "entries": [
    { "name": "bookshelf.json", "kind": "db", "size": 12345, "crc32": "a1b2c3d4" },
    { "name": "bookChapter.json", "kind": "db", "size": 98765, "crc32": "e5f6a7b8" },
    { "name": "book_cache", "kind": "dir", "files": 812, "size": 734003200 }
  ]
}
```

- JSON/XML 条目逐文件记 `size + crc32`；目录类只记文件数与总大小（逐文件 CRC 成本过高）。
- v1 包无 manifest → `format = 1`，按文件存在性推导，走 P0 安全语义。

### 5.2 校验与 UI

- `BackupFileValidator` 增加 `validateManifest()`：格式版本、必填字段、条目 size/CRC。
- 恢复选择器显示：备份时间、设备、app 版本、条目数、总大小、完整性结论。
- CRC 失败或缺关键条目 → 阻断并指出具体条目，不再静默跳过。

### 5.3 覆盖 vs 合并

- 恢复对话框二选一，默认**合并**，文案说明差异。
- 选择覆盖时显示「会删除本地有、备份没有的数据」确认，并默认勾选恢复前快照。

### 5.4 加密

- 整包加密为可选开关：打包后 AES-GCM 加密为 `.zip.enc`，manifest 记 `encrypted=true`；恢复先解密到临时 zip。
- 未设密码时不再用 `MD5("")` 冒充加密：明确提示「未加密」，或拒绝开启整包加密。
- 保留 `BackupAES` 旧字段解密路径，保证旧包可恢复。

### 5.5 保留策略

- 本地/云端按设备分组，各保留 N 份（默认本地 5、云端 30，可配），超出按时间清理。
- 坚果云 700 文件上限从「提示」升级为「按策略自动清理」。

## 6. P2：体积与增量（按需）

### P2a 分卷增量（优先）

- 包拆为 `manifest.json` + `db.zip` + `config.zip` + `cache.zip` + `assets.zip`。
- 每卷记录 size + CRC；本地记录上次各卷哈希，只重传变化的卷；恢复只下载需要的卷。
- 日常自动备份通常只有 `db.zip` / `config.zip` 变化，流量从数百 MB 降到数 MB。

### P2b 对象存储（大改，暂不推荐）

- `.backup/{device}/manifests/{ts}.json` + `objects/{sha256前2}/{sha256}`，manifest 作为原子提交点。
- 支持按需拉取、断点续传、天然去重。
- 代价：WebDAV 请求数上升（坚果云有频率限制），小文件需合并 bundle。

### 顺带性能项

- staging 直写 ZIP，省一次全目录复制。
- 已压缩格式（`.nb`、图片）使用 `STORED`。
- 大表流式 JSON 解析，避免整表进内存。

## 7. 兼容矩阵

| 包形态 | 识别方式 | 删除语义 | 章节处理 |
| --- | --- | --- | --- |
| v1 旧包 | 无 manifest | 条目存在时才允许 Replace | 有 `bookChapterCache.json` 才恢复；有缓存目录则保留现有章节 |
| v2 合并（默认） | `manifest.policyHint = merge` | 只 upsert | `bookChapter.json` + `bookChapterCache.json` 双保险 |
| v2 覆盖 | 用户显式选择 | 有快照才允许 deleteAll | 覆盖后回填缺失书籍的章节 |
| v2 加密 | `manifest.encrypted = true` | 解密后同 v2 | 同 v2 |

## 8. 验证计划

### 8.1 单元测试（纯 JVM）

`RestorePlan.build()` 不依赖 Android，可覆盖：

1. v1 包缺条目 → 计划中无删除步骤；
2. v2 包 manifest 排序 / 过滤；
3. Merge 与 Replace 的策略覆盖；
4. 章节回填触发条件；
5. CRC 失败 → 计划构建失败；
6. 选择器交集过滤。

### 8.2 设备验证

- 4 类包 × 2 策略矩阵，`run-as ... sqlite3` 查 `books` / `book_chapter` 行数。
- 断网（`iptables` DROP 443/80）+ 清空书源后打开缓存书。
- 失败注入：备份中途 `kill -9`、恢复中断网、篡改 CRC。
- 恢复前快照生成与回滚。

### 8.3 指标

- 5000 章目录恢复耗时（目标 < 3s）。
- 日常自动备份上传字节数（P2a 前后对比）。
- 包体积变化（新增 `bookChapter.json` 后）。

## 10. 风险与回滚

| 风险 | 应对 |
| --- | --- |
| 合并语义与「恢复 = 回到备份状态」的直觉冲突 | 显式开关 + 默认文案说明 + 覆盖模式二次确认 |
| 长事务阻塞读写 | 恢复期间锁定阅读入口、全屏进度；恢复前停止缓存任务 |
| 章节全量备份导致包膨胀 | 默认只备有缓存目录的书；全量作为高级开关 |
| 旧包兼容回归 | v1 路径保留独立分支与测试用例 |
| 快照占空间 | 排除缓存/图片，仅保留 3 份 |

## 11. 明确不做

- 行级增量同步（按 `lastModified` 逐行 diff）。
- 多端 CRDT / 冲突合并。
- 跨 DB 版本的数据迁移（仍由 Room migration 负责）。
- 把书籍文件本体（TXT/EPUB）上传 WebDAV。
